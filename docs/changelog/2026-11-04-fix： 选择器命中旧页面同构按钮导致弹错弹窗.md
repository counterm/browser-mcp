# 2026-11-04 · fix: 选择器命中旧页面同构按钮导致弹错弹窗

- 问题：实测 flow（`nav` 到 `/system/menu` → 点左侧「账号管理」→ 点「新增用户」）走到账号管理页后，`click` 的 `selector`（`div.table-box:nth-of-type(2) > … > button`）命中的是**菜单管理页**同位置的「新增」按钮，弹出的是菜单管理的弹窗，后续 `type` / `click` 全部落空。原因是 SPA 路由切换的瞬间旧页面节点还在 DOM 里，位置化选择器照样能命中，`click` 立即返回成功——auto-wait 只兜 `element not found`，这种「找到了但找错了」不会被拦下
- 修复：`content.js` 的 `selectorPick()` 在带 `text` 时先按文本过滤候选（归一化空白 + 忽略大小写 + 包含匹配；录制侧 `text` 只截前 40 字，不能全等）。过滤后为空 → `locate()` 继续走 `text` 兜底，仍找不到就抛 `element not found` → `flowrun.js` 的 auto-wait 每 0.3s 重试，等新页面渲染完再点。录制器本来就给点击步写了 `text`，存量 flow 无需改动
- 边界：`type` 的 `text` 是输入值，不参与同节点校验（`type` / `select` 的 `locate` 调用不带 `text`）；选择器命中的节点文本为空（纯图标按钮）时不过滤，保持旧行为；按钮文案本身随状态变化（如「启用 / 禁用」）的点击步会因校验不过而失败，属预期（宁可报错也不点错节点）
- `node --check` 通过（content.js / flowrun.js）；扩展重载 + 刷新目标页面后生效
