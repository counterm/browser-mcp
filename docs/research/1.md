可以，这条路完全走得通——在 console 里注入一段 JS 建立 WebSocket，正是早期 browser agent 最朴素也最容易跑通的形态。核心原理是：console 里执行的代码运行在页面的主世界（main world），拥有完整的 DOM 读写权、同源 Cookie 和 localStorage，所以只要再开一条双向通道，LLM 就能"看"到页面并"动手"。

最小骨架

页面端（console 里粘贴）：
// 给可交互元素编号，LLM 只用输出数字，比 selector 稳得多
document.querySelectorAll('a,button,input,select,textarea,[onclick]')
  .forEach((el, i) => el.setAttribute('data-bid', i));

const ws = new WebSocket('ws://127.0.0.1:8765');
ws.onopen = () => ws.send(JSON.stringify({type:'hello', url: location.href}));

ws.onmessage = (e) => {
  const cmd = JSON.parse(e.data);
  const el = document.querySelector(`[data-bid="${cmd.bid}"]`);
  switch (cmd.action) {
    case 'click': el?.click(); break;
    case 'type':
      // 直接 el.value = x 对 React/Vue 受控组件无效，必须走原生 setter
      const setter = Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set;
      setter.call(el, cmd.text);
      el.dispatchEvent(new Event('input', { bubbles: true }));
      break;
    case 'scroll': window.scrollBy(0, cmd.dy); break;
  }
  ws.send(JSON.stringify({ id: cmd.id, ok: true, text: document.body.innerText.slice(0,3000) }));
};

// 页面自己变化也主动上报
new MutationObserver(() => ws.send(JSON.stringify({type:'dom_changed'})))
  .observe(document.body, {childList:true, subtree:true});


Agent 端（Python，websockets 库起服务，把页面文本 + 元素列表喂给 LLM，拿回 {"action":"click","bid":7} 下发即可）。

四个绕不开的坑

坑 表现 解法

刷新即失效 一刷新注入的代码全没了，得重新粘贴 改用 CDP 的 Page.addScriptToEvaluateOnNewDocument 自动重注入

CSP 拦截 页面 connect-src 'self' 会挡住 WebSocket CDP Runtime.evaluate 注入（有调试特权）；或换扩展方案

Mixed Content HTTPS 页面连远端 ws:// 会被拦（Chrome 对 localhost/127.0.0.1 放行） 本地用 ws 没问题；跨机用 wss

够不到的地方 跨域 iframe、新开标签、下载、文件上传、beforeunload console 注入无解

工程上为什么大家最终都换成 CDP

纯 console 注入适合做 demo 和一次性任务，真上生产基本都会换：

• CDP（Chrome DevTools Protocol）：chrome --remote-debugging-port=9222 启动后，Runtime.evaluate 注入、Input.dispatchMouseEvent 模拟真实鼠标、Page.captureScreenshot 截图、Page.addScriptToEvaluateOnNewDocument 实现刷新存活。Playwright / Puppeteer / Playwright-MCP 都是这条路，权限最高、最稳。

• 浏览器扩展：content script 常驻 + background 维持 WS，刷新不死、可跨标签，Browser Use 早期版本就是这么做的。

• Userscript（Tampermonkey）：最轻的持久化注入，适合固定几个站点。

想省事的话，直接用现成的 Playwright MCP 或 Browser Use，它们已经把 DOM 简化成 LLM 友好的结构化表示（元素编号 + accessibility tree），比自己撸一遍快照压缩省很多力气。

⚠️ 一点边界提醒：这套能力请用在自己的浏览器自动化、自测脚本或有授权的产品上；用来接管他人会话、绕过风控或验证码，就属于越界了。

你具体想做的是哪种场景——自己电脑上的自动化、给产品做个 AI 助手插件，还是要在无头浏览器里跑批量任务？场景不同，选型差别挺大的。
