# 浏览器插件「站点白名单」功能需求说明

> 版本：v2.0（2026-10-19）
> 适用范围：`chrome-extension/`（Chrome 扩展 MV3）
> 关联现状：早期油猴脚本版（`page-bridge.user.js`，已停止维护、仅作存档）曾有硬编码 `CFG.urlFilter` 正则白名单，本功能将其产品化并落地到扩展版

## 1. 背景与目标

为 `chrome-extension/` 增加站点白名单：决定哪些页面**接入/广播到 broker**。

**采用纯白名单模式**（不提供黑名单、无默认策略开关）：

- **命中白名单**（域名或正则任一）→ 页面正常接入 broker
- **未命中** → 不注册、不广播，外部工具发现不到该页面

功能组成：

| 模块 | 说明 |
|---|---|
| 正则网址配置 | 正则表达式规则，匹配完整 URL，命中即放行 |
| 域名列表管理 | eTLD+1 主域名列表，自动适配所有子域名，支持增删改查 |
| 一键添加/移除 | popup 内一键将当前页面加入/移出白名单 |
| 当前页面状态展示 | 实时展示当前页面是否在白名单及命中来源 |

## 2. 数据结构（chrome.storage）

存储 key：`urlFilterConfig`（`chrome.storage.local`）。

```json
{
  "version": 2,
  "domains": [
    {
      "id": "d_8f3a",
      "host": "example.com",
      "enabled": true,
      "note": "测试站",
      "source": "quick-add",
      "createdAt": 1760000000000
    }
  ],
  "regexes": [
    {
      "id": "r_21c9",
      "pattern": "^https?://.*\\.github\\.dev/",
      "enabled": true,
      "note": "",
      "createdAt": 1760000000000
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `version` | number | schema 版本；v1（旧黑白名单）数据加载时自动迁移：白名单条目保留，黑名单条目丢弃 |
| `domains[].host` | string | 仅存 eTLD+1 主域名（如 `example.com`），存储前强制归一化 |
| `domains[].enabled` | boolean | 停用记录保留但不参与匹配 |
| `domains[].source` | `"manual"` \| `"quick-add"` \| `"import"` | 来源，用于 UI 展示 |
| `regexes[].pattern` | string | JS 正则字符串，匹配完整 URL（含协议、端口、路径、查询串） |
| `id` | string | 生成规则 `d_` / `r_` + 4 位随机，删除后不复用 |

**约束**

- **C1**：同一 `host` 不允许重复（保存时校验）
- **C2**：正则无唯一性约束；重复 pattern 在导入时去重
- **C3**：`host` 一律小写、ASCII 存储

### 2.1 主域名提取（eTLD+1）

内置一份**精简公共后缀表**（覆盖常见多级后缀：`co.uk`、`com.cn`、`com.hk`、`co.jp` 等约 200 条，以常量随扩展发布）。

提取算法（纯函数 `toRegistrableDomain(hostname)`）：

1. 取 hostname，去端口、转小写
2. 若末两段命中后缀表 → 取末三段，否则取末两段
3. 例外输入：
   - IPv4 / IPv6（`[...]`）→ 整体作为一条域名条目
   - `localhost` 及无点单段主机名 → 整体作为一条
   - `file://` 无主机 → 不支持域名匹配，只能被正则规则命中（popup 一键添加对此类页面禁用并提示）
4. 后缀表未覆盖的异常情况降级为末两段，UI 标注「未识别后缀，已按 x.y 处理」

示例：

| 输入 | 提取结果 |
|---|---|
| `gist.github.com` | `github.com` |
| `a.b.example.co.uk` | `example.co.uk` |
| `news.sohu.com` | `sohu.com` |
| `192.168.1.3:8766` | `192.168.1.3` |
| `localhost` | `localhost` |

## 3. 匹配引擎与优先级

匹配实现为 background.js 中的纯函数 `matchUrl(url, config)`，返回 `{allowed, hit}`：

```
matchUrl(url, config):
  domain = toRegistrableDomain(new URL(url).hostname)   // file:// 等为 null
  if domain 命中任一 enabled 域名条目:  return {allowed:true, hit:{kind:'domain', value}}
  if 任一 enabled 正则 pattern.test(url): return {allowed:true, hit:{kind:'regex', value}}
  return {allowed:false, hit:null}
```

**规则要点**：

- 域名规则自动覆盖该主域名下所有子域名（`a.example.com`、`b.c.example.com` 均命中 `example.com`）
- 正则匹配对象为完整 `location.href`（含协议、端口、路径、查询串）
- 域名与正则**地位平等**，任一命中即放行，不比较先后
- 停用（`enabled:false`）的记录不参与匹配，但保留在列表

**对 broker 的语义**：`allowed` 的页面正常注册/广播；未命中的页面不注册。`chrome://`、`chrome-extension://` 等浏览器内部页不受本过滤影响，一律不注入、不广播（与现有 manifest 注入规则一致）。

## 4. 界面布局

### 4.1 Popup（点击工具栏图标，主交互入口）

```
┌─────────────────────────────────────┐
│ [favicon] github.com                │
│ 当前页面状态：● 白名单                │  ← 状态徽章区
│ 命中域名: github.com                 │
├─────────────────────────────────────┤
│ [ 加入白名单 ]  或  [ 从白名单移除 ]  │  ← 一键操作（二态按钮）
├─────────────────────────────────────┤
│ [管理域名列表] [管理正则规则]         │  ← 打开 options 页对应 tab
└─────────────────────────────────────┘
```

**状态徽章**（2 种）：

| 徽章 | 含义 |
|---|---|
| 🟢 `● 白名单` | 命中域名或正则，页面会接入 broker |
| ⚪ `○ 不在白名单` | 未命中任何规则，页面不接入 |

徽章下方注明命中来源（`命中域名: github.com` / `命中正则: ^https?://...`）。

**一键按钮二态逻辑**：

- 页面主域名已在列表 → 显示「从白名单移除」
- 不在列表 → 显示「加入白名单」

**图标角标**：`chrome.action.setBadgeText` 在当前 tab 命中白名单时显示 `W`（绿底），未命中留空。随 `tabs.onActivated` / `tabs.onUpdated` / 配置变更刷新。

### 4.2 Options 页（完整管理）

顶部 Tab：`域名列表` / `正则规则`；公共操作区固定在页底。

#### Tab 1：域名列表

```
┌──────────────────────────────────────────────────────┐
│ [输入任意 URL 或域名…        ] [添加]                  │
│  ↳ 提示: "github.com/gist → 已归一为主域名 github.com"│
├──────────────────────────────────────────────────────┤
│ 搜索 [___________]  [导入] [导出]      共 N 条        │
├──────────┬──────┬────────┬──────────┬──────────────┤
│ 主域名    │ 启用  │ 备注    │ 来源/时间  │ 操作         │
│ example  │ ✅    │ ...     │ 快捷添加  │ 删除         │
└──────────┴──────┴────────┴──────────┴──────────────┘
```

交互要求：

- **添加输入框**接受完整 URL / 子域名 / 裸域名，提交前**自动归一为 eTLD+1** 并显示归一化预览；重复添加被拒绝并提示
- **行内编辑**：启用开关、备注（失焦即保存）
- **删除**：3 秒可撤销（hint 行内「撤销」链接）
- **搜索**：按 host / 备注子串过滤
- **导入**：JSON（同 schema，旧 v1 黑白名单数据中的黑名单条目自动丢弃）或纯文本（每行一个域名或以 `/` 包裹的正则）；文件内去重，冲突/非法条目跳过并在结果中列出
- **导出**：全部配置 JSON

#### Tab 2：正则规则

```
┌──────────────────────────────────────────────────────┐
│ [正则表达式…              ] [添加] [从当前页面生成]    │
│ ↳ 实时校验: ✅合法 / ❌非法正则(错误详情)               │
│ [测试面板: 输入 URL 实时预览匹配结果]                   │
├──────────────────────────┬──────┬────────┬──────────┤
│ pattern                  │ 启用  │ 备注    │ 操作      │
└──────────────────────────┴──────┴────────┴──────────┘
```

交互要求：

- 保存前 `new RegExp()` 校验，非法则禁用提交并显示错误详情
- **测试面板**：输入样例 URL，实时显示 放行/拦截 及命中的具体规则（复用 `matchUrl`）
- 「从当前页面生成」：取 active tab URL，生成转义后的前缀正则（如 `^https?://example\.com/`）

#### 公共操作区（页底固定）

- 导出全部配置 JSON
- 清空全部规则（二次确认）

## 5. 交互流程

| 编号 | 流程 | 步骤 |
|---|---|---|
| F1 | 一键添加当前页 | popup「加入白名单」→ 取 active tab URL → `toRegistrableDomain` 提取主域名 → 写入 storage（`source: "quick-add"`）→ 按钮翻转为「移除」→ 徽章即时刷新 |
| F2 | 一键移除 | 按 host 定位记录（唯一）→ 删除 → 状态回到「不在白名单」 |
| F3 | 配置变更生效 | `storage.onChanged` → background 重算所有标签页 → 不再命中的断开 broker 连接，新命中的补注册（含存量页面）→ **无需刷新页面或重载扩展**，目标 ≤1s |
| F4 | URL 导航 | 页面导航（`nav` 事件 / `tabs.onUpdated` URL 变化）后重新匹配；不再命中则断开 |
| F5 | 非法输入 | 域名输入无法解析出合法 hostname → 输入框红框 + 行内错误，不写入；正则非法 → 同上（显示 `SyntaxError` 详情） |

## 6. 验收标准

1. `https://gist.github.com/xxx` 一键添加后，列表中出现 `github.com`，且 `api.github.com`、`gist.github.com` 均被匹配
2. 多级后缀域名提取正确：`bbc.co.uk` 提取为 `bbc.co.uk`，不会被拆成 `co.uk`
3. 未命中任何规则的页面不出现在 `GET /pages` 中（不注册、不广播）
4. 正则保存非法输入被拒绝；合法正则对完整 URL（含 query string）生效
5. 切换 tab 时 popup 状态徽章与实际匹配结果一致
6. 配置修改后 ≤1s 内对已打开页面生效（连接断开/恢复）
7. 同一 host 不能重复添加；停用的记录不参与匹配但保留在列表
8. `file://` 页面一键添加按钮禁用并提示原因，正则规则仍可匹配 `file://` URL
9. 导入含重复/非法条目的文件时，重复与非法条目被跳过且结果报告准确
10. 旧版黑白名单配置升级后：白名单条目保留，黑名单条目不再生效
